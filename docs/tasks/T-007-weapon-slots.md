# T-007 — Separate gold weapon identifier spike

Status: **READY for expansion**. The first custom pistol identity and controller menu switch passed owner playtesting. Scope: use FusionFix v5.0.1 custom registration to establish separate test pistol, carbine, and shotgun identifiers without changing vanilla weapon definitions. No finished gold art or custom gunplay.

The staged `LF_GOLD_PISTOL` entry copies this machine's base `PISTOL` data and uses the existing `w_glock` model; no external art is redistributed. The source data comes from the owner's installed game. `ExtendedLimits=1` is already set. The first diagnostic script registers `LFWeaponStatus`, `LFWeaponGive`, and `LFWeaponVanilla` console commands. FusionFix's [v5.0.1 source](https://github.com/ThirteenAG/GTAIV.EFLC.FusionFix/blob/v5.0.1/source/limits.ixx) assigns the first custom name ID 58; the live log and owner screenshot confirmed that ID was selected. The guarded installer placed the generated XML at `update/common/data/WeaponInfo.xml`, leaving the original file intact. A hash-checked removal script reverses the override.

The x86 build completed with zero errors/warnings and the staged XML parsed with one original PISTOL and one LF_GOLD_PISTOL. In the first live session, `LFWeaponStatus` logged `candidate_present=False vanilla_present=True`; after `LFWeaponGive`, it logged `current_id=58 candidate_present=True vanilla_present=False`. The owner reported that aim, fire, reload, cover, vehicle, and save/load all passed with the candidate. Thus, the new ID works, but giving it replaces the vanilla pistol in the handgun inventory. The revised DevTools menu has Weapon Status plus guarded give actions. The owner confirmed the menu switching worked; fresh logs show IDs 58 and 7 alternating with total handgun ammo preserved at 226 across several switches. Later ammo fell to 217 during gameplay before another switch, which also preserved 217.

The custom pistol and vanilla pistol cannot be held in the same handgun slot at once with the current data. The controller menu switch is a diagnostic workaround; it transfers total ammo but does not preserve clip state or offer simultaneous inventory coexistence. The stable first pistol permits expanding the identity test to carbine and pump shotgun, with the same inventory limitation expected until tested.

## Human test steps (combine with T-003 after one shutdown)

1. Save and close GTA IV. Rebuild with `./tools/build.ps1 -ScriptHookDotNetReference 'D:\SteamLibrary\steamapps\common\Grand Theft Auto IV\GTAIV\ScriptHookDotNet.asi'` and deploy the revised DLL with `./tools/deploy-t002.ps1 -GameDirectory 'D:\SteamLibrary\steamapps\common\Grand Theft Auto IV\GTAIV'`. The T-007 XML override is already installed and must not be deployed again. The agent performs the DLL install after the owner reports the game closed.
2. Launch GTA IV through Steam. If it fails before gameplay, close it and have the agent run `remove-t007.ps1` while closed; report the startup log. Do not continue this spike after a startup failure.
3. In gameplay, first run T-003's revised menu checks. Navigate to WEAPON STATUS and press Cross/A once; the status should show the selected ID. The console commands remain available as a fallback but are no longer required for this test.
4. Navigate to GIVE TEST PISTOL and press Cross/A twice, releasing between presses. The second press confirms the action. Expect `current_id=58` and `candidate_present=True` in `scripts/LibertyFramework/logs/LibertyFramework.log`. The test pistol looks like the vanilla pistol. If it does not select cleanly, stop the weapon checks and report the log.
5. Close the menu. Aim and fire with the candidate. Reopen the menu and use GIVE VANILLA PISTOL (two presses) to verify switching back. WEAPON STATUS should show the selected ID and total handgun ammo; compare ammo before and after each switch. The candidate's earlier aim, fire, reload, cover, vehicle, and save/load checks passed. Record any mission or death behavior only if naturally encountered; do not force a mission reset.
6. Report weapon status lines, gameplay behavior, and any crash or visual problem. The agent inspects logs and either marks the first identity proved or revises the route. The override stays a private diagnostic until the slot and asset path are validated.
