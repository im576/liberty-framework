# T-028 — Liberty Content Compiler v2: native texture dictionaries

Status: **NEEDS-PLAYTEST**

Depends on: M4 content compiler v1 (in game 2026-09-25, `docs/content/README.md`).

## Scope

Roadmap step 2 of [the content compiler](../content/README.md#roadmap), texture half: write texture dictionaries (`.wtd`)
from scratch instead of patching the template's pixels.

- `textureMode` in `asset.json`: `"template"` (default, unchanged v1 behaviour) or `"native"`.
- Native mode keeps the template drawable path (same texture name), but writes the dictionary with
  `TextureDictionaryWriter`: the source texture at its own size (nearest power of two, 4–2048), the full mip chain down
  to a 4-pixel side, DXT1, or DXT5 when the material is not opaque and a pixel is translucent.
- New DXT5 encoder (both alpha modes) and a DXT1/3/5 reference decoder in `tools/models`.
- Read-back in native mode checks format, size, level count and every level byte for byte, decodes the top level and
  measures it against the source (`textureQuality` in `report.json`, floor 20 dB).
- Validator groundwork for multi-material, multi-LOD writers: an IR (`ContentLod`, `ContentMaterialGroup`),
  `CompilerCapabilities` (v1: 1 material per LOD, LOD 0 compiled), new codes LCC024 (LOD outside 0–3) and LCC025 (LOD
  validated, not compiled).
- `LibertyContent selftest` (offline, 168 checks) runs in `package-phase2.ps1` before any asset is built.
  `LibertyContent wtdcheck` rebuilds the game's own dictionaries with the writer and compares them (read only).
- Blender add-on 0.2.0: **Texture mode** setting, written to `asset.json`.
- Test assets: `content/props/lf_native_crate` (the sample crate, native DXT1) and `content/props/lf_alpha_panel`
  (generated by its `source/make_lf_alpha_panel.py`, native DXT5). Autopilot scenario `native-texture-review`.

No gameplay code, native or memory access changes. Vanilla is untouched: the new props exist only in
`LibertyContent.img` and appear only when a script spawns them.

## Offline evidence (2026-09-26, cloud agent; no game available)

- Build: the `build-content.ps1` source set compiles with Roslyn (the .NET 8 SDK's `csc`, `/langversion:7.3`,
  `/platform:x86`, warnings as errors, CS0649 off) against Mono's .NET Framework 4.5 reference assemblies: 0 errors,
  0 warnings. `tools/build-content.ps1` itself (Windows, pinned Roslyn 4.11) has not been run.
- `selftest`: `passed=168 failed=0`. Mutating the name hash, the hash sort, the page-straddle rule, the mip-level count or
  the DXT5 8-value mode each makes it fail.
- `wtdcheck` on the self-test's own dictionaries: 5 files rebuilt, 5 identical.
- `validate`: all four assets under `content/props` pass. The native texture path (everything except capturing the
  template's dictionary) on the new assets: `lf_native_crate` 256×256 DXT1, 7 levels, 38.1 dB; `lf_alpha_panel` 128×128
  DXT5, 6 levels, 46.0 dB colour, alpha exact.
- Blender 4.2 (`bpy` module): the add-on registers; Export writes `"textureMode": "native"` only in native mode, and LBX020
  is worded per mode. The headless suite (`tools/blender/run-tests.ps1`) needs the game and was not run; its new case 3b
  covers a native build.
- Fixed on the way: GDI+ resampling faded alpha at image edges (seen with Mono's libgdiplus; Windows GDI+ not
  checked), which would make opaque textures translucent at their border in native mode. Native mode now resamples
  with its own edge-clamped tent filter.

## Open questions (answered by the steps below)

1. Do the writer's rules hold for the game's dictionaries? Name hash, hash order, row stride (+0x24) and the full-chain
   mip rule were matched against `coronas.wtd`, `hud.wtd` and `amb_nailgun.wtd` while the writer was written. The
   builtin prototype bytes and the record's +0x40 word (written as 0) have not been compared with game files.
2. Does the game load a dictionary whose graphics segment is one page (the writer's choice up to 8 MB)? One page is what
   made generated drawables render ([ModelFormat.md](../research/ModelFormat.md#in-game-finding-one-graphics-page-for-generated-models-2026-09-25)).
3. Does `gta_default` draw DXT5 alpha translucent, cut out, or opaque?

## Human test steps

Steps 1–2 are read only and safe while GTA IV runs. Step 3 needs the game closed.

1. **Build and self-test.** From the repository root: `./tools/build-content.ps1`, then
   `./tools/content/bin/LibertyContent.exe selftest`. Expect `selftest: ok passed=168 failed=0`.
2. **Compare the writer with the game's dictionaries.** Run
   `./tools/content/bin/LibertyContent.exe wtdcheck --game '<GTAIV folder>' pc/models/cdimages/weapons.img`.
   Archive paths are relative to the game folder. To include loose dictionaries, also pass the full path of a folder of
   `.wtd` files (for example wherever `coronas.wtd` and `hud.wtd` were read from). Paste the whole output into the report.
   Expect `failed=0`, `rebuilt` equal to `identical`, `nameHash` and `rowStride` equal to `textures`, and
   `record+0x40: ... other=0`. Any `other=` count or `rebuilt differs` line is a finding, not a reason to stop.
3. **Package and install.** With GTA IV closed:
   `./tools/package-phase2.ps1 -GameDirectory '<GTAIV folder>' -ScriptHookDotNetReference '<ScriptHookDotNet.asi>'`
   (it runs the self-test, then builds all four content assets), then
   `./tools/install-phase2.ps1 -GameDirectory '<GTAIV folder>'`.
   In `staging/phase2-reports/content/lf_native_crate/report.json` expect `"status": "ok"`, `"textureMode": "native"`,
   `"textureFormat": "DXT1"`, `"textureLevels": 7`; for `lf_alpha_panel` expect `"textureFormat": "DXT5"`,
   `"textureLevels": 6` and a `textureQuality` with `psnrAlphaDb`. Also open `lf_alpha_panel_texture.png` in that folder:
   a dark frame, a red diagonal and a checker of translucent blue/white cells.
4. **In game.** Run
   `./tools/autopilot/Run-Scenario.ps1 -GameDirectory '<GTAIV folder>' -Scenario tools/autopilot/scenarios/native-texture-review.txt -OutputDirectory <runs folder>`.
   Expect every step OK in `report.md` and five screenshots:
   - `native_crate_front`, `native_crate_side`: the native crate (front) and the template crate (behind) both textured
     with the "LIBERTY SUPPLY" planks, identical in colour and sharpness, no garbage, no missing texture (white/grey).
   - `alpha_panel_front`, `alpha_panel_angle`, `alpha_panel_back`: a standing panel with a dark frame and a red diagonal.
     Report what the checker cells do: see-through to the crate/park behind (translucent), holes (cut out) or solid
     blue/white (alpha ignored). All three are useful answers.
5. If the game crashes or a prop is invisible, attach `scripts/LibertyFramework/logs/LibertyFramework.log` and the
   run's `report.md`. Rollback: `./tools/rollback-phase2.ps1 -GameDirectory '<GTAIV folder>'`.
