# T-031 Bronx east graphics layout diagnostic

Read-only run of `LibertyContent roundtrip` built from `773a528` against `pc/data/maps/east/bronx_e.img`. Content selftest passed **358/358**. The targeted archive contained 352 drawables; 187 were eligible for this structure writer, 105 rebuilt identically and 82 differed. There were no archive errors. The command correctly returned failure for the 82 differences. `roundtrip.json` includes `graphicsLayouts` for the first 25 failures, with source and rebuilt page metadata, buffer ranges and aggregate byte classes for unmodeled source ranges. It includes no resource bytes.

For example, `agld04_03.wdr` has 786,432 source graphics bytes and 118,784 rebuilt bytes. Its source ranges outside the currently modeled vertex/index buffers contain many nonzero, non-CD bytes, so treating all of those ranges as padding is unsupported. The report also records embedded texture dictionary presence. This is diagnostic evidence, not a writer fix or full drawable roundtrip.

Five previously unreadable archives were independently inspected without printing the AES key or resource data. Each file is exactly 2,048 bytes. Decrypting the first 32 bytes with the existing `ImgArchive` key and routine yielded IMG v3 magic `0xA94E2A52`, version `3`, count `0`, table size `0` for each: `pc/data/maps/generic/lodcull_j.img`, `lodcull_m.img`, `pc/data/maps/interiors/test/interiors.img`, `pc/data/maps/leveldes/levelmap.img`, and `TLAD/pc/data/maps/interiors/int_test.img`. This proves they are valid encrypted empty IMG archives; the current reader error comes from attempting to decrypt a zero-length table.
